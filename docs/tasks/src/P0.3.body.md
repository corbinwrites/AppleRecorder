## P0.3: make the spec executable (strong model or human only)

Goal: after this step every behavior in Part 2 is a compiling stub plus a failing test. Weak agents then only have to turn red into green. You need a Mac with Xcode, because this step must **compile**.

Read `docs/BUILD-GUIDE.md` Part 2 (section 21 to 33) in full, and `docs/API-NOTES.md`.

### Steps

1. **Stubs.** For every public type, function and protocol in Part 2, create the stub at the exact path and signature the guide gives. Throwing functions: `throw TODO.notImplemented`. Non-throwing: `fatalError("TODO")`. Define `public enum TODO: Error { case notImplemented }` in `Core`. Add explicit `public init`s to every public struct (the guide's section 24.1 says to; its code omits them). No logic in stubs.
2. **Seeded tests.** The agent kit already placed these complete files. Keep them as they are:
   - `Packages/Core/Tests/CoreTests/CoreTests.swift` (state machine, capture mode, session store, settings)
   - `Packages/Core/Tests/CoreTests/HelperTests.swift` (session grouping, timecode, meter, progress bar)
   - `Packages/Capture/Tests/CaptureTests/AudioTestHelpers.swift`
   - `Packages/Capture/Tests/CaptureTests/FinalizerStereoTests.swift` (one of ten Finalizer tests)
   - `Packages/Enhance/Tests/EnhanceTests/NotesPipelineTests.swift` (two of ten pipeline tests)
3. **Write every other prose-specified test.** One `@Test` per bullet. One row of a table = one argument of a parameterized `@Test(arguments:)`. Copy numbers and strings exactly. Do not paraphrase expected values.

4. **Resolve these gaps in the guide** (decide, implement the stub, and note the decision in `docs/API-NOTES.md`):
   - `ProcessingStage` is now defined in section 24.7 (Rev 5). Put it in `Core`.
   - `TranscribeOrchestrator` and `TranscribeError.engineFailed(stage:)` appear only inside test prose (26.3). Define their signatures: orchestrator takes an engine, a mode, the audio file and a temp directory, and returns `[TranscriptSegment]`.
   - `AppModel` is used by the views but several members are never declared: `player`, `reveal(_:)`, `retranscribe(_:)`, `requestDelete(_:)`, `acknowledgeConsent()`, `chooseNotesFolder()`, `chooseAudioFolder()`, `confirmDiscard()`, `cancelProcessing()`, `importAudioPanel()`. Stub them in `App/AppModel.swift`.
   - `Session.init(title:mode:)` has only a comment. Implement the defaults the comment lists (stub-free, trivial).
5. **Delete** every `PlaceholderTests.swift` once its package has real tests.
6. **Cross-check** table-driven tests against `docs/reference/validate_logic.py` if it exists. If Python disagrees with a table in the guide, write `BLOCKERS.md` instead of choosing.
7. **Compile check.** In every package: `swift build --build-tests` must succeed. Then `swift test` must fail only by assertion or `TODO`. A compile error is a bug in this step. Fix it before tagging.
8. **Tag.** Commit, then `git tag spec-v1` and `git push origin main spec-v1`. After the tag, `scripts/protect-tests.sh` forbids changing any of these test files. Only a human moves the tag.

### Rules for this step

- Do not implement logic. A stub that "just works" hides a missing test.
- If a guide test cannot compile as written (for example `.init(...)` inference on an `Optional` parameter), change it to the explicit type and list the change in `docs/API-NOTES.md`. These are the only edits to the seeded files allowed, and only before the tag.
- Fast loop: `swift test --filter <Suite>`. A `fatalError` stub crashes the whole test process, so filter by suite.
